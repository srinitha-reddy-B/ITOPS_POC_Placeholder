# ITOps Command Center: architecture note

This is an upgrade of the existing `/p32` application. The backend, the agent orchestration and the sequential pipeline are unchanged. The new pages read the same run records and connection status the existing pages use.

## Architecture

| Layer | What it is |
|---|---|
| `backend/` | FastAPI, API only (port 8001): agent runtime (Cohere, JSON contract, validation, one retry), ServiceNow and predictive tools, approval role checks, audit |
| `frontend/server.mjs` | Dependency-free Node server (port 3000): serves `/` and `/p32`, proxies `/api/*` to the backend |
| `frontend/src/p32/parts/*` | The ITOps app: plain JavaScript parts built into one page (`npm run build`) |

Agent pipeline (unchanged, strictly sequential):

1. Intake
2. Triage
3. Evidence
4. Hypothesis
5. Critic
6. Judge (up to 2 rounds)
7. RCA Writer
8. Quality gate
9. **Engineer approval**
10. SOP
11. **SOP approval**
12. Execution (simulated)
13. Verification
14. Closure

The asset and HR flows have their own sequences, each with a manager or HR-partner gate.

## What was added

| Page (route) | Who | Data |
|---|---|---|
| Command Center (`#/command-center`) | IT Administrator, IT Engineer | Workbench runs, predictions and connection status (actual); service health (simulated telemetry) |
| SSO Investigation (`#/sso-investigation`) | IT Administrator, IT Engineer, Leadership | **Demo:** deterministic walkthrough built from the SSO scenario's scripted evidence. **Live:** only real events (live sign-in signal, real agent calls, RCA run). Missing stages stay empty. |
| Service Dependency Graph (`#/dependency-graph`) | IT Administrator, IT Engineer | Synthetic relationships (labelled); health from the simulation or the live SSO signal. Live mode has no per-node telemetry, so nodes show "No telemetry". |
| Agent Execution (`#/agent-execution/<incident>`) | IT Administrator, IT Engineer | The run record: per-step status, source, duration, input, output, tools, retries |
| Observability (`#/observability`) | IT Administrator, IT Engineer, Leadership | Telemetry trends (simulated; SSO sign-ins and incident frequency live in Live Agent Mode); agent history and durations (actual runs) |
| Incident page tabs: Timeline, ServiceNow work notes | Engineer (others view only) | Run events and approvals. Notes are marked **Posted** only when the ServiceNow call succeeded. |
| DEMO-PAY-048 | Engineer | The documented ITOPS demo (INC0010048, Payment API cold-start HTTP 504) restored as a curated incident. In Live Agent Mode it binds to the real INC0010048 by number. |

## Choices and why

- **No React, React Flow, Framer Motion or Recharts.** The frontend was just made dependency-free (`no npm install`), and the app is plain JavaScript. The graph and animations use SVG (`animateMotion`) and CSS; the charts reuse the page's existing chart helpers. Animations are turned off when the user prefers reduced motion.
- **No graph database, RAG or GraphRAG.** The dependency graph is a frontend visualisation of labelled synthetic relationships.
- **Live never fabricates.** Live views use only recorded events; demo views carry a "Demo / simulated" tag.

## Backend changes (minimal, justified)

- `p32_workbench_data.json`: added DEMO-PAY-048 (generated by `backend/scripts/add_inc0010048.py`).
- `p32_workbench.py`:
  - `sn_bind` binds a curated incident by its `servicenow_number` when it has one (otherwise by the existing tag).
  - Seeding skips such incidents, so no duplicate of INC0010048 is created.

## Tests

`cd frontend && npm test` checks that:
- the page builds and every inline script parses
- 6 personas × 19 routes enforce the access rules
- the action guard works
- rules-v2 scoring gives the expected results, including that factors with no data are excluded
- the asset and HR forecasts are correct
- the SSO walkthrough stops at the approval
- INC0010048 runs end to end in Controlled Demo Mode

## Known limits

- Service telemetry is simulated, except the SSO sign-in signal; SOP execution is simulated.
- Live Agent Mode for DEMO-PAY-048 writes work notes and the resolution to the real INC0010048 after the engineer's approvals.
